# 跑团桌 · 单房间 DND 5e 在线跑团平台

一个网页，所有人打开同一个地址就是同一张桌子：1 个主持人 + 若干玩家。
不需要注册、房间码、匹配大厅。服务端是唯一真实来源，**所有骰子都在服务端结算**。

---

## 一、启动

### 双击（Windows）
双击 `启动服务.bat`，会自动打开浏览器到 `http://localhost:8081`。

### 一条命令
```bash
node server.js
```

然后打开 `http://localhost:8081`。

改端口 / 监听地址：
```bash
PORT=9000 HOST=127.0.0.1 node server.js
```

**依赖：只需要 Node.js 18+（用到全局 fetch），零第三方包。** 不用 `npm install`。

### 多人怎么试
打开页面先选一个**玩家名**当账号。同一个浏览器**多开几个标签页**，各自选不同玩家名，就是多个玩家同时在线。
或者让同一局域网的朋友访问 `http://你的内网IP:8081`（HOST 默认 `0.0.0.0`）。

### 消息语法（**仅「自动」类型生效**，支持一行内混写）
| 输入 | 结果 |
|---|---|
| `#他推开门` 或 `*他推开门` | 动作（青色 `»` 斜体）。**一个标记就够**；写成 `*他推开门*` 也行，收尾的 `*` 会去掉 |
| `（我今晚来不了）` / `(english)` | 皮下 / 场外：显示成系统提示那一行的居中细字「**玩家名：内容**」，不可回复 |
| `{1d20+3}` | 行内骰：服务端掷骰，消息里显示为「1d20+3 = 15」的芯片；内容不参与 `#` / `（` 拆分 |
| 其它文字 | 角色发言 |

**标记出现在哪就在哪切开，一条输入会拆成多条消息依次发出。**

输入区四个按钮：**自动**（默认）/ 角色发言 / 动作 / 皮下。只有「自动」做上面的识别；选了「角色发言 / 动作 / 皮下」就是整条按该类型原样发，`#` `*` `（）` 都当普通字符（想打出这些符号本身就切到对应按钮）。

例：`测试 #123 （什么）` 发送后是三条：

| 类型 | 内容 |
|---|---|
| 角色发言 | 测试 |
| 动作 | 123 |
| 皮下 | 什么（显示为「玩家名：什么」的居中提示行） |

其它例子：

- `（笑）我们走吧` → 皮下「笑」+ 角色「我们走吧」
- `他说：#跑 （好的） 然后走了` → 角色「他说：」+ 动作「跑」+ 皮下「好的」+ 角色「然后走了」
- `*他推开门` → 动作「他推开门」（没写收尾 `*` 也认）

**防误伤**：`#` 和 `*` 只有在「行首」或「前面是空格 / 标点 / 右括号」时才算标记，所以 `2*3=6`、`C#` 这类不会被切开。括号（全角半角都认）永远算标记，没写右括号就一直取到结尾。

解析在服务端做（`parseSegments`），以服务端结果为准——前端改不了判定。

### 导出 LOG
侧栏「导出 LOG」→ 下载 `.md`，按频道分组、按**你的身份**裁剪（别人看不到的私聊不会出现在你的导出里），消息标注 `[游戏内]/[动作]/[场外]/[叙述]/[掷骰]/[战斗]`。

## 三、数据存储（可插拔）

默认**内存模式**：改完即用，重启进程全部清空。

要落库，配置两个环境变量（密钥只在服务端，前端拿不到）：

```bash
SUPABASE_URL=https://xxxx.supabase.co \
SUPABASE_ANON_KEY=eyJhbGciOi... \
node server.js
```

Windows 下：
```bat
set SUPABASE_URL=https://xxxx.supabase.co
set SUPABASE_ANON_KEY=eyJ...
node server.js
```

然后在 Supabase SQL Editor 执行 `schema.sql`（可重复执行）。启动日志会打印 `存储：PostgREST` / `存储：内存`，侧栏右上角也有标记。

两种模式共用同一套业务逻辑，只是换了个 `store` 实现：内存是数组，数据库是 PostgREST 的 REST 读写。

### 三个必须知道的坑（都已在代码里处理）

1. **混合大小写列名**：PostgREST 大小写敏感。`ownerClientId`、`maxHp` 这类列必须用双引号建列（见 `schema.sql`），请求体字段名也要大小写完全一致，否则报 `42703 column does not exist`。

2. **新增字段是幂等的、但不会回填旧数据**：
   `ALTER TABLE ... ADD COLUMN IF NOT EXISTS "channel" text DEFAULT 'main'` 对**已存在**的行不会写入默认值，历史消息的 `channel` 仍是 `NULL`。所以 `schema.sql` 里跟了一句
   ```sql
   update public.messages set "channel" = 'main' where "channel" is null;
   ```
   否则这些老消息按频道过滤时会被漏掉。`pos` 同理（用 `seq` 回填）。

3. **`normalize` 不能全量覆盖**：如果把 PATCH 请求直接归一化再写回，没带的字段会被重置成默认值（只改 `hp` 会把名字、职业、状态全清空）。
   现在的做法是：**先读现有记录 → 合并请求里带的字段 → 再归一化 → 写回**（`server.js` 的 `updateCharacter` / `normalizeCharacter`）。客户端也只发有变化的字段。

## 四、账号、角色卡与怪啖论坛接入

### 账号 = 玩家名
- 打开页面先选一个**玩家名**，它就是账号，**不需要密码**。
- 这个玩家名下的角色，就是这个账号的角色卡：比如「空理鹊(kuuku)」名下有 2 个人物 → 侧栏 2 张卡，窗口上限也是 2+1=3。
- 账号存在 `sessionStorage`（标签页级）：同一标签换账号点右上角「切换」；多开标签选不同玩家名 = 多个玩家同时在线。
- 主持人唯一：已有主持人时其他人认领会被拒绝（409）；主持人可主动「释放」。
- **没有鉴权**：知道玩家名就能进，也能编辑/扮演该玩家名下的卡。可见性（私主持人/定向）只防误看、不防伪造。内部自用。

### 分页（一页 = 一个频道）
- 每一页是**一个频道**的窗口（boluo 的 Pane）。页头显示频道名；同一频道的消息全服同步。
- 点侧栏频道 → 当前**聚焦页**切到这个频道；频道行悬停的「+」在新页里打开它。
- 顶栏「新分页」优先挑一个还没被任何页显示的频道，**最多 4 页**；点页头 ✕ 收起，**至少保留一页**。
- 拖页头左侧六点把手可以左右调顺序，刷新后保持。
- 每页各自记住 **说话身份（哪张角色卡）/ 类型 / 可见性 / 搜索**，互不影响。
- 点哪一页，哪一页就是聚焦页：侧栏频道高亮、顶栏显示、战斗事件都跟着它。

### 主持人（DM）的工具

- **认领 / 释放**：侧栏「主持人」，同一时间只有一个人能当。
- **发言凸显**：主持人的每条消息带琥珀色左条和「主持人」徽标，方便在一堆角色发言里一眼找到。
- **房间公告**：顶栏「公告」写一段所有人可见的公告（集合时间、房规、本场须知），可改可删；其他人点公告条可展开全文。
- **折叠消息**：消息「⋮」→「折叠这条」，正文收起成「已折叠」，玩家可点开看，日志不丢——比删除更适合处理剧透/跑题。
- **正在输入**：别人在这个频道打字时，消息区下方会显示「XX 正在输入…」。
- **成员面板**：侧栏「成员」列出主持人、每个玩家及其角色（头像 / HP / 最后发言时间），点角色能直接打开卡。
- **GM 笔记**：成员面板底部，只有主持人能读写的备注（NPC、伏笔、暗血、暗骰）。服务端会给非主持人的 `state` 里去掉这个字段。
- **管别人的消息**：主持人和作者本人都能编辑/删除消息；别人的消息里只有主持人能改。
- **战斗面板**：开战掷先攻、逐轮推进、对任意目标 ±HP/移除，PC 掉血自动写回角色卡。
- **导出 LOG**：按频道分组导出 markdown。

### 角色卡字段来自论坛

| 论坛字段 | 用途 |
|---|---|
| `playerName` | 玩家名 → **账号** |
| `archive.realName` | 角色名（展示用，**不是** `nickname` 网名） |
| `avatar` | 头像（复制到本项目 `avatars/`，离线也能显示） |
| `nickname` | **不使用** |

论坛卡只有身份信息，没有 DND 数值，导入后卡片标「待补全」；点开补六维 / HP / AC / 职业即可。

### 同步行为
- 启动时如果本地一张卡都没有，自动从论坛 `db.json` 导入一次。
- 侧栏「角色卡」右上角刷新按钮 = 手动再同步。
- 卡 id 固定为 `gd-<论坛用户id>`，**幂等**：重复同步不会产生重复卡。
- **只更新** 角色名 / 玩家名 / 头像，**不覆盖** 你填的 DND 数值、状态、备注。
- 跳过 11 个空角色名或玩家名为 `unknown` 的测试号。

### 数据源路径
默认读 `E://绘画//2026//企划//怪啖论坛//Web//data//db.json`，可用环境变量改：

```bash
GUAI_DAN_DB="D://某处//db.json" node server.js
```

头像从同目录 `files/avatars/` 复制到本项目 `avatars/`。

### 如果要做得更硬
1. **认领密码**：首次进入某个玩家名时设一个密码，之后凭密码进入，避免别人直接顶号。
2. **真鉴权**：上账号体系（OAuth / Supabase Auth）+ RLS 按 `auth.uid()` 过滤，此时 `clientId` 由服务端从会话里取，而不是前端传。
3. 论坛卡以后若加了 DND 字段，扩展 `server.js` 里 `readForumCards()` 的映射即可。


## 五、API

全部 JSON，只有 `/api/export` 返回 markdown 附件。

```
GET  /api/state?since=<seq>&me=<clientId>   角色卡 / 消息（增量 + 可见性裁剪）/ 房间状态 / 规则表
GET  /api/export?me=<clientId>              整场 LOG（markdown 附件，按频道分组、按身份裁剪）

POST /api/dm                { clientId, name, release? }      认领 / 释放主持人
POST /api/character         { clientId, ...角色字段 }          新建
POST /api/character/update  { id, clientId, ...要改的字段 }     局部更新（合并后写）
POST /api/character/delete  { id, clientId }
POST /api/forum/sync        {}                            // 从论坛 db.json 幂等同步角色卡
POST /api/message           { kind, role, author, text, visibility, audience, sender, channel }
                            // text 按标记切成多段 → 返回 { messages: [...] }，一段一条
POST /api/check             { characterId, skill|ability, dc, mode, sender, channel }
POST /api/damage            { expr, author, role, sender, channel, mode }
POST /api/combat/start      { clientId, monsters:[{name,hp,ac,init?}] }
POST /api/combat/next       {}
POST /api/combat/end        {}
POST /api/combat/patch      { targetId, delta|hp|remove|addMonster }
POST /api/channel/create    { name }
POST /api/channel/rename    { id, name }
POST /api/channel/delete    { id }           // 至少留一个；消息并入第一个剩余频道
POST /api/message/move      { seq, targetSeq, position:'before'|'after', sender }
POST /api/message/update    { seq, sender, text }          // 只能改自己的（或 DM）
POST /api/message/delete    { seq, sender }                // 只能删自己的（或 DM）
POST /api/announcement      { text, clientId }             // 只有主持人能改，text 为空即删除
POST /api/message/fold      { seq, sender }                // 只有主持人，切换折叠状态
POST /api/typing            { channel, characterId, sender } // 上报「正在输入」，6 秒过期
POST /api/gm/notes          { text, clientId }             // 只有主持人；别人的 state 里没有 gmNotes
```

返回里的 `error` 字段是给前端 toast 用的；HTTP 状态码也正确（400/403/404/409/500）。

## 五点五、模仿 boluo 的部分

交互参考了 [mythal/boluo](https://github.com/mythal/boluo)（面向跑团的聊天应用）：

| boluo | 这里的对应实现 |
|---|---|
| Pane（可开关、可拖动排序的聊天分栏） | 分页：一页 = 一个频道，页头把手拖动排序 |
| `{1d20}` 行内表达式 | `{1d20+3}` 行内骰，服务端结算后渲染成芯片 |
| compose 的实时预览（`makeDesiredPreview`） | 输入框上方的「将发出 N 条」预览，按类型标注 |
| 频道未读提示 | 侧栏频道小蓝点 |

有意的不同：boluo 用 `.in` / `.as` / `.ra` 前缀修饰符控制「是否在戏内、以谁的身份、掷什么」，这里按你的要求改成**三个类型按钮 + `#` `*` `（）` 行内标记**；说话身份放在输入区的角色卡下拉里，一页一个频道。

## 六、拖拽重排是怎么做的

1. `pointerdown` 记起点；移动超过 7px 才真正开始（不影响点击和选中文字）。
2. 克隆一条 `.ghost`，`position: fixed` 跟手（`translate3d`），原位插入等高占位 `.msg-ph`。
3. 每次 `pointermove` 拿鼠标 Y 和各消息中线比较，把占位插到该处；插入前后对各邻居做 **FLIP**（记录旧 `rect.top` → 插入后算位移 → `translateY(旧-新)` → `requestAnimationFrame` 归零，过渡 220ms）。
4. 松手：ghost 平滑落回占位框（220ms），然后 `POST /api/message/move`，服务端重算整条频道的 `pos` 并持久化，客户端重新拉取。
5. **拖到最末尾**时占位前一条就是最后一条可见消息，`position: 'after'` + 该 `seq`；直接用 `before` 会落到倒数第二位。
6. 列表按 `(pos ?? seq)` 排序渲染。

> 注意：如果频道里存在你**看不到**的消息（别人的私主持人消息），它在服务端仍占一个位置。你拖到最末尾时，消息会落在最后一条**可见**消息之后——对你的视图来说确实在最末，服务端的那条隐藏消息可能排在它后面，这是符合预期。

## 七、已知限制

- 单选房间：所有连接共享同一房间状态（`room_state` 只有 `id=1` 一行），这是「单房间」的设计前提。
- 轮询而非推送：客户端每 2 秒增量拉取一次，够用但不是 websocket。
- 战斗只有先攻条和 HP，没有网格、距离、掩体、法术位、豁免/伤害类型。
- 撤销/删除消息未实现（日志是账本，尽量不删）。
- 没有移动端专门适配，窄屏会横向滚动窗口。
